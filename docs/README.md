## Documentation Standards

### File Naming
- Use UPPERCASE_WITH_UNDERSCORES.md
 5. [TESTING_GUIDE.md](./TESTING_GUIDE.md) - API testing
 6. [DEPLOYMENT.md](./DEPLOYMENT.md) - Deploy locally
- H1 title at top
- Table of contents for files > 100 lines
- Code examples with proper syntax highlighting
- Clear sections with H2 headers
- Links to related documents

### Maintenance
- Update when features change
- Keep version number in footer
- Mark as "Last Updated: [DATE]"
- Request review from relevant team

### Useful Commands

**Development:**
```bash
# Get running locally
cd backend && pnpm install && pnpm start:dev

cd frontend && pnpm install && pnpm dev
```

**Testing:**
```bash
# Run all tests
pnpm test

# Run with coverage
pnpm test:cov

# E2E tests
pnpm test:e2e
```

**Database:**
```bash
# Migrations
pnpm prisma migrate dev

# Studio
pnpm prisma studio

# Seed data
pnpm seed
```

**Deployment:**
```bash
# Build
pnpm build

# Deploy
vercel --prod  # Frontend
railway deploy # Backend
```

## Contributing to Documentation

### Adding New Documentation

1. Create file with descriptive name: `FEATURE_NAME.md`
2. Add to appropriate section above
3. Update "Documentation Status" table
4. Add version: 1.0 and current date
5. Link from relevant existing docs
6. Update this index file

### Documentation Checklist

- [ ] Clear title (H1)
- [ ] Table of contents if > 100 lines
- [ ] Descriptive paragraphs
- [ ] Code examples with syntax highlighting
